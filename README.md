# Одиннадцатый спринт

Проект для компании «Будущее 2.0»: переход от общего DWH к доменной событийной архитектуре и самообслуживанию в аналитике.

Подготовлены решения всех пяти заданий. [Требования и порядок работы](docs/plan.md).

[Сверка пяти заданий и оставшиеся условия сдачи](docs/readiness.md).

| Каталог | Содержание |
|---|---|
| Task1Advanced | Terraform-модуль ВМ и окружения dev, stage, prod |
| Task2Advanced | Удалённое состояние и CI/CD |
| Task3Advanced | C4, риски и меры снижения |
| Task4Advanced | Bounded contexts, агрегаты и события |
| Task5Advanced | Техрадар, TCO и роадмап |

Медицинские карты, истории болезней и результаты исследований не входят в аналитическую витрину. Доступ к медицинским данным для лечения и ИИ должен остаться в отдельном операционном контуре.

В локальном приватном Jenkins выполнены настоящие plan → input → apply для dev, stage и prod. ВМ, диски, закрытые security groups и outputs каждой среды сверены с облачным API и зашифрованным S3 state. После проверки stage её ВМ и два диска удалены по отдельному согласию для экономии квоты; история проверки и сеть сохранены. [Результаты и подтверждения](docs/deployment-results.md).

Реальные S3-проверки подтвердили шифрование KMS, versioning, conditional writes и изоляцию сред. Конкуренция двух процессов Terraform проверена на отдельном синтетическом state. GitHub Actions содержит только проверки без облака; настоящий deployment выполнялся в Jenkins. Планы, state, ключи и полные журналы в репозиторий не включены. Учебные ВМ не являются развёрнутой платформой из проектных C4-схем.
