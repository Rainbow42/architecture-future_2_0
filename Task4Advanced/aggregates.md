# Агрегаты и инварианты

Транзакционная граница проходит по агрегату в БД его контекста. Внутри неё сохраняются изменение состояния и запись outbox. Между контекстами нет общей транзакции: результат чужого действия подтверждается событием, а ошибки обрабатываются повтором или компенсацией.

| Контекст / корень агрегата | Ключ | Состав и инварианты | События |
|---|---|---|---|
| Реестр пациентов / Patient | (clinic_network_id, patient_id) | Контакты и версии согласий; patient_id неизменяем, слияние дублей требует отдельной операции и аудита. Наличие PatientRegistered само по себе не означает согласие на любой вид обработки | PatientRegistered, PatientConsentChanged |
| Запись / Appointment | (clinic_id, appointment_id) | Пациент, слот, статус и версия; подтверждение возможно только для действующего резерва. Терминальная отмена не обращается поздней оплатой автоматически | AppointmentReserved, AppointmentConfirmed, AppointmentCancelled |
| Запись / SlotCapacity | (clinic_id, resource_id, slot_start) | Счётчик и резервы; сумма действующих резервов не больше доступной ёмкости. Резерв имеет срок, повтор команды с тем же request_id не занимает второй слот | CapacityReserved, CapacityReleased |
| Расчёты / Invoice | (legal_entity_id, invoice_id) | Строки, валюта, итог, подтверждённые оплаты и возвраты. Сумма неотменённых возвратов не превышает подтверждённые оплаты; отмена счёта не стирает проводки | InvoiceIssued, InvoicePaid, RefundIssued |
| Кредитование / CreditAgreement | (bank_id, agreement_id) | Версия условий, сумма, валюта, срок, статус подписания и выдачи. Одни подписанные условия нельзя молча заменить; выдача только по действующему одобренному договору | CreditAgreementCreated, CreditDisbursementRequested |
| Банковский учёт / PostingBatch | (bank_id, posting_id) | Набор проводок одной операции; дебет равен кредиту для каждой валюты, operation_id уникален. Проводки, проверка лимитов и изменение остатков фиксируются одной транзакцией банковского ядра | FundsDisbursed, DisbursementRejected |
| Фарма / ProductionBatch | (manufacturer_id, batch_id) | Спецификация, сырьё, результаты контроля и статус. Выпуск запрещён без завершённого контроля; отозванная партия не может снова стать доступной к отгрузке простой правкой статуса | BatchReleased, BatchRecalled |
| Электроника / DeviceUnit | (manufacturer_id, serial_number) | Версия модели, комплектующие, испытания, статус. Серийный номер уникален у производителя; выпуск только после успешных испытаний, отзыв блокирует дальнейшую отгрузку | DeviceReleased, DeviceRecalled |
| Снабжение / StockPosition | (warehouse_id, sku_id, lot_or_serial_id) | Доступно, зарезервировано, отгружено; резерв не превышает доступный остаток. Использование конкретной партии разрешено только после подтверждения выпуска и при отсутствии отзыва | MaterialsReserved, MaterialReservationRejected, StockAdjusted |
| ИИ / ResearchJob | (tenant_id, research_id) | Версия входа и модели, попытки выполнения, состояние и защищённая ссылка на результат. Одновременно только одна активная попытка заданной версии; готовый результат не перезаписывается без новой версии | AIResearchCompleted, AIResearchFailed |
| Корпоративные финансы / ConsolidationPeriod | (group_id, period, currency) | Версии доменных сводок, корректировки, статус закрытия. Закрытый период изменяется отдельной корректировкой с новой ревизией; исходные книги не редактируются | FinancialPeriodClosed, FinancialPeriodCorrected |
| Каталог / DataProductVersion | (domain_id, product_id, version) | Контракт, владелец, классификация, контрольная сумма набора, проверки качества. Публикация только после успешной проверки схемы и допуска; опубликованный набор неизменяем | DataProductPublished, DataProductWithdrawn |

## Конкуренция и связи между агрегатами

Optimistic locking по версии агрегата защищает от потери обновлений. Для денежных остатков используются транзакционные блокировки/ограничения банковского ядра, а не только проверка версии потребителем Kafka. Глобальное «exactly once» между БД, брокером и внешним банком не предполагается.

Appointment и SlotCapacity — разные агрегаты одного контекста. Сначала команда резервирования атомарно меняет SlotCapacity. Затем идемпотентная команда создаёт Appointment с reservation_id. При сбое создание повторяется; просроченный неиспользованный резерв освобождается. Между резервом и созданием записи слот может временно оставаться занятым, но двойное бронирование не допускается. Подтверждение сначала атомарно переводит действующий резерв в закреплённый в SlotCapacity, конкурируя с его истечением через проверку версии. Затем идемпотентно подтверждает Appointment. Закреплённый резерв не освобождается по прежнему таймеру. При сбое второй операции процесс повторяется, а при окончательной отмене выполняется явное освобождение.

Резерв нескольких StockPosition оформляется процессом с reservation_id: частичный успех компенсируется освобождением уже занятых позиций. Внешний процесс не получает MaterialsReserved, пока не собран полный набор. Отзыв партии блокирует новые резервы и запускает разбор уже отгруженных партий; событие само по себе не гарантирует мгновенную физическую остановку отгрузки.

## Компенсации

- Оплата после истечения резерва: запись не восстанавливается, создаётся запрос на возврат с ключом payment_id. Ошибка возврата попадает в отдельную очередь разбора, а не теряется вместе с отменённой записью.
- Неуспешная выдача кредита: договор остаётся в состоянии ожидания/ошибки выдачи, повтор использует прежний operation_id. Новая команда не создаёт вторую проводку.
- Повтор AIResearchCompleted: тот же research_id + result_version не создаёт второй клинический результат. Исправление модели — новое задание/версия, а не перезапись истории.
- Ошибочный продукт данных: версия отзывается, доступ запрещается, подписчики получают DataProductWithdrawn и удаляют/блокируют свои копии по процедуре владельца. Новая версия не делает прежнюю ошибку незаметной.

Все перечисленные ключи включают границу организации. Нельзя объединять одинаковый patient_id или serial_number из разных компаний. Для переноса истории используется явная таблица соответствий внутри контекста-владельца, недоступная общему BI.
