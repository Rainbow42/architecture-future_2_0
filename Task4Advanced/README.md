# Домены и интеграции

Разделила клиники, банк, производство и общую аналитику по владельцам данных и правилам изменения состояния. Диаграммы описывают целевое решение, а не уже развёрнутые сервисы.

- [Границы контекстов](bounded-contexts.svg), [исходник](bounded-contexts.puml), [описание связей](contexts.md).
- [Event Storming для записи и оплаты](event-storming.svg), [исходник](event-storming.puml).
- [Агрегаты, ключи и инварианты](aggregates.md).
- [События, контракты и правила доставки](events.md).
- [Почему события вместо общего Camel/DWH](justification.md).

Клинические документы и результаты исследований не публикуются в аналитическую платформу. События лечения и ИИ остаются в медицинском контуре. Общая аналитика получает только отдельно подготовленные разрешённые продукты данных.

Проверка синтаксиса и сборка диаграмм:

```sh
plantuml -checkonly Task4Advanced/bounded-contexts.puml Task4Advanced/event-storming.puml
plantuml -tsvg Task4Advanced/bounded-contexts.puml Task4Advanced/event-storming.puml
```

Task4 подготовлен как проектное решение. Согласование с владельцами доменов, нагрузочные проверки и испытания интеграций в работающей системе в учебном проекте не проводились.
