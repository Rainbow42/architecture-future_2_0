# Условие и порядок работы

[Проектная работа 11 спринта](https://practicum.yandex.ru/learn/software-architect-pro/courses/9ce77cf1-e2d2-4867-b2d1-1da1f54ad30f/sprints/810692/topics/195188f2-e13a-43c0-a691-ba30bfa44271/lessons/cbef31d8-11f8-45ae-a3e4-63fe53a97884/). Все пять заданий повторно прочитала в штатном интерфейсе.

В начале условия указано имя репозитория `architecture-future_2_0`, а в конце — `architecture-future_pro_2_0`. Выбрала имя из инструкции по подготовке. Основные каталоги называются `Task1Advanced`–`Task5Advanced`, как в требованиях сдачи. Отличающиеся имена каталогов в отдельных примерах не дублируются.

## Что нужно подготовить

1. Переиспользуемый модуль `modules/vm`: CPU, RAM, подключаемый диск, subnet ID и SSH-ключ. Три независимых корневых конфигурации dev/stage/prod, свои tfvars, outputs и инструкция применения.
2. S3-совместимое удалённое состояние, отдельные ключи и права для сред, блокировка состояния. Pipeline init → plan → apply с ручным подтверждением; секреты вне репозитория.
3. C4 уровня контейнеров и компонентов на горизонт трёх лет. Карта архитектурных, организационных и технических рисков: вероятность, влияние, владелец, меры и сигнал срабатывания.
4. Bounded contexts; агрегаты с инвариантами и ключами; Event Storming; каталог событий с источниками, подписчиками и минимальными контрактами. Обоснование замены Camel/DWH событиями.
5. Расширенный техрадар Adopt/Trial/Assess/Hold; TCO текущей и целевой архитектуры на три года; роли и этапы Data Mesh.

## Границы решения

- Task1 прямо требует три конфигурации dev/stage/prod со своими tfvars; критерии ревью включают применение разных конфигураций через `terraform apply -var-file=...`. Постоянная или одновременная работа трёх сред не требуется: учебные проверки можно выполнять последовательно.
- Yandex Cloud — выбранный провайдер реализации, а не обязательное требование. Task2 допускает MinIO, Yandex Object Storage или AWS S3; Jenkins также выбран для реализации, условие допускает другую CI/CD-систему.
- Task3–5 требуют проектных артефактов, а не развёртывания всей целевой платформы. Бизнес-цель портала не означает требование реализовать работающий портал в этой проектной работе.
- Портал и аналитические продукты не получают медицинские карты, истории болезни и результаты исследований, в том числе из сырых зон и событий.
- Общие показатели строятся по разрешённым доменным продуктам, а не по копии всех таблиц SQL Server.
- SQL Server 2008, PowerBuilder и Camel выводятся постепенно через антикоррупционные слои, без остановки клиник и банка.
- Горизонты: согласование границ за два месяца; пилот за 0–6 месяцев; расширение за 6–18; уход от легаси-интеграций за 18–36.
- Расходы на учебную проверку разрешены в пределах согласованного гранта; ресурсы нужно экономно переиспользовать. Внешний доступ, identities и выдача новых прав согласуются отдельно. До настоящего применения Terraform форматирование, валидацию и mock-проверки нельзя выдавать за развёртывание.
- Теория и личный опрос завершены, десятый спринт принят. Перед сдачей проверить все пять заданий. По последнему прямому указанию пользовательницы готовый PR отправляется в Практикум без отдельного просмотра и повторного подтверждения; описание PR оставить пустым. Input deployment pipeline остаётся; последующие обычные create/update делегированы после проверки полного плана, стоимости, квот и state. Удаления, новые права и публичный доступ этим не разрешены.

## Текущий этап

Подготовила Terraform-модуль Task1Advanced, целевую архитектуру и риски Task3Advanced, домены и события Task4Advanced. Для Task3 есть ландшафт, C4 контейнеров и компонентов, этапы перехода и 12 рисков с мерами. Для Task4 — две схемы, агрегаты, контракты и обоснование интеграций. В Task5 подготовила техрадар, воспроизводимый трёхлетний TCO с явными допущениями и роадмап Data Mesh. В Task2 подготовила генератор раздельных S3 backend, policy-шаблон, Jenkinsfile с сохранённым планом и ручным input. GitHub workflow выполняет только проверки без облака. Чувствительные планы и аварийный state остаются на приватном агенте, не в GitHub artifacts.

Личный облачный аккаунт активирован, billing привязан, создан учебный каталог to-future-sprint. По разрешению пользовательницы создан отдельный Terraform-аккаунт с правами Compute/VPC только на учебный каталог; ключ хранится вне репозитория, аутентификация и чтение каталога через API проверены. Рабочие профили не использовались для облачных операций. Параметры сред уменьшены под текущие зональные квоты.

Созданы приватный бакет с versioning и шифрованием KMS, отдельный ключ, три state-аккаунта без ролей на каталог, локальный Jenkins и изолированный Linux-агент без монтирования домашнего каталога. Временные права настройщика сняты, ключ отозван. Реальные S3-проверки подтвердили шифрование, версии, conditional writes и изоляцию трёх сред; настоящий lock Terraform проверен двумя процессами. Личный доступ владелицы сохранён, доступ служебного прокси не добавлялся. По отдельному разрешению подготовлены read-only plan-аккаунт, SSH-пара, ключи Jenkins и три deployment jobs.

Настоящие stage build 1, prod build 2 и dev build 4 завершились SUCCESS. ВМ, диски, закрытые SG и outputs каждой среды сверены с API/KMS state. Предыдущие частичные отказы dev на HDD в зоне a и prod на квоте VPC сохранены в истории. После разбора guards архивированы с записью сверки, затем созданы новые планы; старые apply не повторялись, state push/force-unlock не выполнялись. Prod переиспользует ранее созданный data-диск и отдельно согласованную VPC stage через data source.

После проверки stage по отдельному согласию удалены только её ВМ и два диска, чтобы освободить квоту зоны d для dev. Сеть, подсеть, SG, backend и история сохранены. С отдельным согласием заменена пустая dev-подсеть a→d, затем применён новый dev-план. Stage input владелица нажала самостоятельно; prod/dev inputs нажаты делегированно. Input, аутентификация и sandbox не отключались. Исторический stage output vm после targeted cleanup не выдаётся за живую ВМ. Полные результаты и несекретные скриншоты — в [отчёте](deployment-results.md).

SSH-вход и нагрузочные испытания не проводились и не заявляются. Теория и личный опрос завершены.
