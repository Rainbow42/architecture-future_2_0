# Проверки

## Task1Advanced

Terraform 1.12.2, провайдер yandex-cloud/yandex 0.237.0.

- `terraform fmt -check -recursive Task1Advanced` — пройдено.
- `terraform init -backend=false` и `terraform validate` — пройдено для dev, stage и prod.
- Проверка плана с mock-провайдером — по одному успешному сценарию для каждой среды. Проверены имя из tfvars, CIDR подсети, отсутствие публичного IP и запрет входящего трафика без явного списка адресов.
- Файлы фиксации провайдера содержат контрольные суммы для darwin_amd64, darwin_arm64, linux_amd64 и linux_arm64, полученные через официальное зеркало Yandex Cloud.
- На локальном Linux ARM64 агенте повторно прошли fmt, init без backend с readonly lockfile, validate и три mock-сценария. Это проверяет переносимость конфигураций и пакета провайдера, но не создаёт ресурсы облака.
- После уменьшения конфигураций под учебные квоты повторно прошли fmt, init без backend, validate и все три mock-плана. Дополнительные assertions ограничивают примеры двумя vCPU и суммой HDD не более 20 ГБ на среду; интерфейс переиспользуемого модуля эти ограничения не навязывает.
- По разрешению пользовательницы создан учебный сервисный аккаунт Compute/VPC с правами только на учебный каталог. Ключ сохранён вне репозитория с правами файла 0600 и каталога 0700. Аутентификация через официальный IAM API и чтение списка зон/ВМ прошли; список ВМ пуст. Найден образ Ubuntu 24.04 с минимальным диском 10 ГБ. Эти запросы не создавали ВМ и не подтверждают работоспособность развёртывания или лицензионную стоимость образа.
- Отдельно проверен конкретный образ fd8u4slqk48lj887qjad: Compute API вернул READY и минимум 10 ГБ, а [официальная карточка Ubuntu 24.04 Vanilla](https://yandex.cloud/ru/marketplace/products/yc/ubuntu-24-04-lts) указывает именно этот образ и тип тарификации Free. Этот вывод не переносится автоматически на последнюю версию семейства и не означает бесплатные CPU/RAM/диски.

Повторить проверки плана из корня репозитория после init:

```sh
for env_name in dev stage prod; do
  mkdir -p "Task1Advanced/envs/$env_name/.terraform/checks"
  cp Task1Advanced/checks/environment.tftest.hcl "Task1Advanced/envs/$env_name/.terraform/checks/"
  terraform -chdir="Task1Advanced/envs/$env_name" test \
    -test-directory=.terraform/checks -var-file="$env_name.tfvars" || exit 1
done
```

Значения folder/image и открытый SSH-ключ внутри проверки синтетические. Они используются только mock-провайдером.

Реальный `apply`, удалённый backend и CI/CD ещё не проверены. Mock-сценарий не подтверждает права в облаке, доступность образа, квоты, создание ВМ или доступ по SSH.

## Task2Advanced

- Генератор backend: разные ключи dev/stage/prod, отдельные префиксы перечисления workspaces, нативный lock-файл, HTTPS и отсутствие credentials в HCL. Сгенерированный HCL разобран настоящим `terraform fmt` без обращения к backend.
- `node Task2Advanced/checks.mjs` — пройдено: привязка к среде, commit, run/attempt, версии, backend и входным параметрам; отказ при изменении плана или истечении срока.
- `node Task2Advanced/pipeline-checks.mjs` — пройдено с локальной заглушкой Terraform: выключенный deployment не вызывает CLI, apply использует сохранённый plan без нового plan, неверные параметры и повторный apply отклоняются. При ошибке синтетические логи и аварийный state остаются приватными, новый запуск блокируется маркером восстановления.
- GitHub workflow проверок разобран actionlint 1.7.12. Shellcheck и pyflakes не запускались. Node-синтаксис скрипта проверен отдельно. Настоящий Declarative Pipeline linter локального Jenkins 2.580.1 принял текущий Jenkinsfile: `Jenkinsfile successfully validated.` Deployment pipeline ещё не выполнялся.
- Добавлены режим bucket-kms и обязательный preflight до Terraform: точный KMS-ключ, versioning, ACL и политика HTTPS. Локальные негативные проверки отклоняют неверный ключ, отсутствие шифрования, публичное Allow и отсутствие запрета HTTP. При ошибке preflight заглушка Terraform не вызывается. Это проверки логики, а не реальные операции S3.
- Созданы приватный бакет с лимитом 1 ГБ и versioning, отдельный KMS-ключ, три state-аккаунта без ролей на каталог. Их ключи сохранены вне репозитория. Применены точные state/lock/verification policy, HTTP deny, чтение метаданных одного бакета и encrypt/decrypt одного ключа. GetBucketPolicy, GetBucketAcl и GetBucketVersioning прошли всеми тремя identities. GetBucketEncryption вернул 404 ServerSideEncryptionConfigurationNotFoundError: шифрование по умолчанию пока не настроено. State и пробные объекты не записывались; это не успешная проверка шифрования.
- Настоящий backend-preflight для dev/stage/prod отказал с exit=1 из-за отсутствующей SSE-конфигурации. Уточнена проверка регистра ключа aws:securetransport, который консоль возвращает строчными буквами; scoped HTTP-deny с дополнительными условиями отклоняется. Скрипт storage-checks.mjs пока проверен только синтаксически и не выполнял запись.
- Подключён постоянный локальный Linux ARM64 агент `future-terraform` с одним executor. Проверены отсутствие mount домашнего каталога хоста и версии Node.js 22.23.3, Terraform 1.12.2, Java 21. Контроллер слушает только loopback, анонимный запрос получает 403, исполнителей на контроллере нет; FileVault на хосте включён.
- Настоящий Jenkins job `future-agent-check`, build 1: SUCCESS. На агенте выполнились команды проверки версий и отсутствия конфигурации хоста. Облачные credentials не выдавались; plan/input/apply в этом запуске отсутствовали.
- Повторно прошли fmt, init без backend, validate и три mock-плана Task1. Проверки не создают ресурсы.

Настоящие Jenkins plan/input/apply, запись backend и конфликт блокировок ещё не проверены. Контроллер, агент и точечные права подготовлены; шифрование бакета, deployment jobs и облачные credentials в Jenkins ещё не настроены. Платные облачные ВМ не запускались. В GitHub workflow нет deployment jobs. Чувствительные планы/state/полные логи не отправляются в GitHub artifacts.
