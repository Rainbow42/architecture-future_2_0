Повторить проверки плана из корня репозитория после init:

```sh
for env_name in dev stage prod; do
  mkdir -p "Task1Advanced/envs/$env_name/.terraform/checks"
  cp Task1Advanced/checks/environment.tftest.hcl "Task1Advanced/envs/$env_name/.terraform/checks/"
  if [ "$env_name" = prod ]; then
    cp Task1Advanced/checks/prod-network.tftest.hcl "Task1Advanced/envs/$env_name/.terraform/checks/"
  fi
  terraform -chdir="Task1Advanced/envs/$env_name" test \
    -test-directory=.terraform/checks -var-file="$env_name.tfvars" || exit 1
done
```

Значения folder/image и открытый SSH-ключ внутри проверки синтетические. Они используются только mock-провайдером.

Реальное применение всех трёх конфигураций Task1 через Jenkins подтверждено отдельно от mock-проверок: см. [итоговые результаты](deployment-results.md) и хронологию ниже. Mock-сценарий сам по себе не подтверждает права в облаке, доступность образа, квоты, создание ВМ или доступ по SSH.

```sh
node scripts/validate-docs.mjs
node scripts/calculate-tco.mjs --check
node Task2Advanced/checks.mjs
node Task2Advanced/pipeline-checks.mjs
actionlint -shellcheck= -pyflakes= .github/workflows/terraform.yml
git diff --check
```
