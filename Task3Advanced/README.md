# Целевая архитектура и риски

Предложила целевую архитектуру на три года и переход к ней без одновременной замены всех систем. Бизнес-правила остаются в доменах; общая платформа отвечает за публикацию разрешённых продуктов, каталог и доступ к аналитике.

- [Ландшафт систем](landscape.svg) — клиники, банк, новые производства и временное легаси; [исходник](landscape.puml).
- [C4: контейнеры аналитической платформы](containers.svg); [исходник](containers.puml).
- [C4: компоненты сервиса публикации](publication-components.svg); [исходник](publication-components.puml).
- [C4: компоненты API портала](portal-components.svg); [исходник](portal-components.puml).
- [Решения, сценарии и этапы перехода](architecture.md).
- [Карта рисков и меры](risks.md).

Медицинские карты, истории болезни и результаты исследований исключены из платформы целиком, а не только из интерфейса витрины. Клинические операции и медицинский ИИ остаются в отдельном контуре. Состав и договорённости доменов приведены в [Task4](../Task4Advanced/contexts.md).

На схемах контейнер — приложение или хранилище, компонент — часть одного приложения. Границы и подписи уровней соответствуют [C4 Container](https://c4model.com/diagrams/container) и [C4 Component](https://c4model.com/diagrams/component). Инфраструктурные реплики и зоны доступности описаны отдельно в тексте, чтобы не смешивать их с логическими уровнями.

Диаграммы описывают проектное решение, не результат развёртывания. Образы ВМ из Task1 — учебная инфраструктура; три ВМ сами по себе не реализуют эту платформу.
